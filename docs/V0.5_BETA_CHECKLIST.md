# Fly Eye v0.5 Beta Release Checklist

v0.5 Alpha feature scope is frozen. Beta work is validation, production integration, and hardening only.

## 1. Production deployment

- [ ] Vercel daily deployment quota has reset
- [ ] Deploy current `main` containing v0.5.0-alpha.7+
- [ ] Confirm production bundle version
- [ ] Confirm main camera runtime still uses `escape-fast-v1`
- [ ] Confirm 70K graph is never downloaded until Advanced Mode is explicitly requested

## 2. Supabase / leaderboard

- [ ] `SUPABASE_DB_URL` available to production Serverless Functions
- [ ] `GET /api/health` returns database=true
- [ ] First request creates/verifies `fly_eye_scores`
- [ ] Sneak Up score submission succeeds
- [ ] Scare Fast score submission succeeds
- [ ] Server score matches local estimate
- [ ] One UUID appears only once on leaderboard using its personal best
- [ ] Invalid UUID rejected
- [ ] Implausible Scare Fast latency (<250 ms) rejected
- [ ] Verify connection strategy is suitable for Vercel Serverless; use Supabase pooler URL if direct Postgres connectivity is unstable

  - Target: `cname.vercel-dns-0.com`
  - Proxy: DNS only during Vercel verification
- [ ] Verify Vercel domain ownership/configuration
- [ ] Verify HTTPS certificate
- [ ] Verify camera permission works on `https://fly.fde.fan`
- [ ] Remove or disable the DNS setup endpoint after successful provisioning
- [ ] Cloudflare token should have only the minimum Zone DNS Edit permission for `fde.fan`

## Beta exit criteria

Call the release `v0.5.0-beta.1` only after:

1. production deployment is live;
2. Supabase API is verified against the real database;
3. `fly.fde.fan` serves valid HTTPS;
4. iPhone Safari rear-camera matrix passes;
5. no known false-escape regression from normal handheld jitter;
6. deliberate fingertip approach works >=80% in the chosen test protocol;
7. all CI checks are green.

# Fly Eye v0.5 — Productization Plan

## Goal

Turn Fly Eye from a camera/connectome prototype into a reliable, understandable, shareable mobile experience.

v0.5 should **not** add many new neural claims before the current camera → perception → escape pathway is stable. The priority is to make one interaction feel unmistakably real:

> Move a fingertip toward the fly → perception recognizes a valid approach → LC4/escape pathway activates → the fly reacts → replay explains why.

## Product principles

1. **Camera-first.** The real world remains the main input surface.
2. **Instant start.** Camera mode must never wait for the 70K neuron graph.
3. **Perception and brain stay separate.** Users should always know whether a failure is camera interpretation or neural response.
4. **No fake precision.** Aggregate profiles are labeled aggregate; neuron-level graphs are labeled neuron-level.
5. **Mobile is the primary layout.** Data must never cover the interaction itself.
6. **Every visible string is bilingual (EN / 中文).**
7. **Raw camera frames stay local.**

## P0 — Reliability before new features

### 1. Interaction calibration wizard

After camera permission:

- 1.0–1.5 s camera stabilization
- camera shake baseline
- hand tracker status
- fingertip confidence
- connectome runtime status
- one short guided gesture: "Move one finger toward the fly"

The app should confirm:

- HAND / FINGERTIP detected
- CAMERA stable enough
- APPROACH signal responds
- VALID LOOM can exceed threshold

If the semantic hand tracker is unavailable, explicitly switch to:

> Optical mode

instead of silently behaving differently.

### 2. Perception confidence model

Expose a single internal confidence object:

```js
{
  cameraStable,
  handConfidence,
  fingertipConfidence,
  opticalLoomConfidence,
  approachConfidence,
  finalLoomConfidence
}
```

The final neural input should be derived from these confidence-weighted signals rather than multiple hidden thresholds.

### 3. False-positive / false-negative test matrix

Minimum manual device tests:

- iPhone Safari rear camera
- iPhone Safari front camera
- Android Chrome rear camera
- desktop Chrome webcam

Scenarios:

- camera opens, no hand movement → no escape
- normal handheld jitter → no escape
- hand moves sideways → low/no escape
- fingertip approaches fly → approach rises
- fingertip stops very near fly → short persistence, then decay
- entire camera pans → compensated as camera motion
- partial fingertip with no full hand → optical fallback still works

Acceptance target:

- < 5% false escape rate in 20-second idle test
- >= 80% successful response across 10 deliberate fingertip approaches
- camera challenge usable within ~2 seconds after permission when assets are warm

## P1 — Replay 2.0

Replay becomes the main educational payoff.

### Replay scene

Show together:

- camera frame
- fly at its recorded position/state
- fingertip / hand landmark overlay when available
- fly-centered looming zone
- LC4
- left/right DN
- flight output
- threat / escape

### Causal timeline

Example:

```text
-940 ms  fingertip enters fly zone
-610 ms  approach confidence rises
-430 ms  validated looming
-280 ms  LC4 response
-140 ms  DN / flight output
   0 ms  escape
```

Do not imply biological millisecond precision unless the timing is actually from the model. UI copy should say "model timeline" where appropriate.

### Replay controls

- play / pause
- scrub
- 0.25× / 0.5× / 1×
- show/hide perception layer
- show/hide brain layer

## P1 — Two game modes using the same validated escape pathway

Do not create new neural claims yet.

### Mode A — Sneak Up

Goal:

> Get as close as possible without triggering escape.

Score candidates:

- minimum fingertip distance
- maximum threat below escape threshold
- time spent in high-alert zone

### Mode B — Scare Fast

Goal:

> Trigger the escape circuit as quickly as possible after READY.

Measures:

- valid looming latency
- LC4 response latency
- modeled escape latency

These two modes reuse the same validated pathway but create different play styles.

- generate a compact result card
- bilingual caption
- challenge link
- score

- "real MaleCNS aggregate connectivity + modeled dynamics" disclosure

## P1 — FlyEye Graphs developer package

Publish the current fast profile as a supported asset:

```text
/data/escape-fast-v1.json
```

Add:

- JSON schema
- TypeScript type
- provenance
- source commit/hash
- scientific boundary
- example parser
- example group-level simulator

Suggested JS API:

```js
import { loadFlyEyeProfile, EscapeRuntime } from "@fly-eye/graphs";

const profile = await loadFlyEyeProfile("escape-fast-v1");
const runtime = new EscapeRuntime(profile);
const state = runtime.step({ looming: 0.7 });
```

This can later become its own package only after the API is stable.

## P2 — Optional neuron-level advanced mode

The detailed neuron-level graph should be explicitly opt-in:

> Load neuron-level view

It must:

- lazy-load only after camera mode is already usable
- show exact download size before downloading
- show real progress
- cache locally
- never block gameplay

Use it for:

- advanced Brain view
- pathway inspection
- comparison with aggregate runtime
- validation experiments

---

## P2 — Validation layer

For identical prerecorded looming inputs, compare:

```text
escape-fast-v1 aggregate runtime
vs.
neuron-level escape subset
```

Track:

- LC4 response shape
- DN response order
- flight output
- escape threshold timing

The aggregate runtime should be treated as a product approximation and calibrated against the more detailed graph, not independently hand-tuned forever.

---

## Not in v0.5

Do **not** add yet:

- olfaction
- taste
- sound
- arbitrary object recognition
- LLM vision
- multi-animal simulation
- full 166,700-neuron real-time simulation
- generic "build a world" editor

These can wait until the camera interaction itself is stable and shareable.

---

## v0.5 release criteria

Ship v0.5 only when:

1. camera opens without the fly escaping by itself
2. deliberate fingertip approach consistently produces APPROACH / VALID LOOM
3. Fly reacts on supported phones
4. no blocking 70K graph download
5. Replay shows the fly, perception evidence, and neural response
6. mobile camera view remains mostly unobstructed
7. every visible user-facing string works in EN and 中文
8. fast graph profile and scientific boundary are documented
9. warm repeat visit works without long model/download waits
10. at least one shareable result flow is complete
